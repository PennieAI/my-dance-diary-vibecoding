# 产品口播框架

## 核心选题

我如何用 Vibe Coding，把一张静态舞蹈课表变成会记录成长的练舞日记。

## 目标听众与价值

- 听众：对 Vibe Coding 感兴趣、但不知道能做什么真实产品的人；以及想系统记录练舞的人。
- 价值：看见一个从个人痛点出发、能够日常使用的完整产品，而不只是一次性网页 Demo。

## 核心逻辑

1. 痛点：纸面课表只能告诉我“有什么课”，不能告诉我“上过什么、表现如何、坚持到了哪里”。
2. 产品：把月/周课表、打卡、自评、课程难度、舞力和单节课价连成一个反馈闭环。
3. Vibe Coding：通过持续描述需求、看效果、再微调，让不熟悉前端开发的人也能把个人工作流做成产品。
4. 开源：公开版本使用匿名示例配置，其他人可以替换自己的课表和目标。

## 结构

- 0–15 秒：从“买了年卡，但不知道自己到底跳得怎么样”切入。
- 15–55 秒：展示核心交互和舞力计算方式。
- 55–80 秒：说明 Vibe Coding 的价值与迭代过程。
- 80–95 秒：开源与行动邀请。

## 注意事项

- 不公开真实课表、老师姓名、金额或个人打卡记录。
- 不把 Vibe Coding 说成“一句话自动完成”，强调持续表达、验证和迭代。
